个人项目最容易失控的地方是配色：每加一个组件就想再调一次颜色。约束的办法是把色板锁死到三个值，其余全部由它们派生。

## 三个值

```
前景 #87c5d1   背景 #e9feff   侧栏 #cee9ee
```

这三个值定义的是**表面**。文字不直接使用前景色，因为 `#87c5d1` 落在 `#e9feff` 上只有 **1.84:1** 的对比度——远低于正文所需的 4.5:1。

实测一下：

```bash
# 相对亮度
#87c5d1 -> 0.4969
#e9feff -> 0.9543

# 对比度 = (0.9543 + 0.05) / (0.4969 + 0.05) = 1.84:1
```

## 派生文字阶

正确的做法不是放弃这套配色，而是从同一色相推导出加深的文字阶：

```css
@theme {
  --color-accent: #87c5d1;      /* 前景色：装饰、色块、强调 */
  --color-ink-strong: #17414d;  /* 标题   12.4:1 */
  --color-ink: #2c6473;         /* 正文    6.3:1 */
  --color-ink-soft: #3f7a88;    /* 次要    4.6:1 */
}
```

色相没变，观感仍然是同一套配色，但正文可读了。

### 暗色模式同样要单独测

把浅色的通过结果直接继承过去是错的。`#2c6473` 在深色底上几乎不可见。暗色模式需要一整套独立的令牌，由同一色相家族重新推导，而不是机械反转。

```css
.dark {
  --color-canvas: #0f2a30;
  --color-ink: #cbe6ec;
}
```

## 一条经验

如果某个颜色让你反复犹豫，那通常说明它不该存在。锁死的色板带来的最大收益不是好看，而是**决策次数的减少**。
