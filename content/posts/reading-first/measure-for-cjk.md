66 字符是拉丁排版的经验最优值，它来自一个隐含前提：**一个字符承载的信息量大致恒定**。这个前提在中文里不成立。

## 字符数不等于信息量

汉字是表意文字，一个常用字平均承载的信息量约等于 2–2.5 个拉丁字母。同样一句「今天天气很好」，中文 6 个字，英文 `the weather is nice today` 是 22 个字符。

所以当你把 `max-width: 65ch` 用在中文正文上，读者一行要处理的信息量大约是拉丁文本的 **2.5 倍**。眼睛在行末回扫时的定位难度随之上升——这正是"读起来累"的来源。

## 中文的舒适区间

中文正文的经验区间是 **30–45 字/行**：

| 每行字数 | 体验 |
| --- | --- |
| < 25 | 回扫过于频繁，节奏被打断 |
| 30–45 | 舒适区，长篇阅读不易疲劳 |
| > 50 | 回扫开始出错，必须借助手指或鼠标 |

实现上，`ch` 在中文环境下恰好等于一个汉字宽度（全角），因此直接收紧数值即可：

```css
.reading-column {
  /* 面向中文的度量：约 38 字 */
  max-width: 38em;
  font-size: 1.125rem;
  line-height: 1.8;
}
```

如果站点是中英混排，取两者的折中值更实际：

```css
.reading-column {
  /* 中文不至于太宽，英文不至于太窄 */
  max-width: 42em;
}
```

## 行高也要跟着改

汉字是方块字，字面率高，行与行之间天然缺少拉丁文字那种由升降部形成的视觉间隙。同样的行高，中文看起来更挤。

- 拉丁正文：`1.5–1.6`
- 中文正文：`1.75–1.9`

这不是审美偏好，是字形结构决定的。把 `line-height` 从 `1.6` 提到 `1.8`，中文段落的可读性提升比换字体明显得多。

### 首行缩进还是段间距

两者选一个，不要都用。中文传统排版用首行缩进（`text-indent: 2em`），网页环境更适合段间距——因为屏幕上的段落长度差异远大于纸质书，缩进在短段落上会显得突兀。

```css
.reading-column > * + * {
  margin-top: 1.4em;
}
```

## 标点挤压

中文标点是全角，但句号、逗号、顿号的实际字形只占半角宽度，两边各留四分之一空。连续标点时会形成明显空洞：

> 他说：「这样，也行。」

严格的中文排版需要对标点做挤压（`text-spacing-trim`），现代浏览器已经支持：

```css
.reading-column {
  text-spacing-trim: trim-start;
}
```

实际效果因字体而异，在正文里影响有限，但标题和引用块上差别肉眼可见。

## 结论

不要照搬拉丁排版的经验值。度量取决于**每行承载的信息量**，而不是字符数——这也是为什么同一套设计规范在不同语言下必须重新推一遍，而不是翻译一遍。
