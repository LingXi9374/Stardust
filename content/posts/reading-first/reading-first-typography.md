一个阅读页面的全部设计，几乎都可以归到三个数字上：**行长、行高、层级比例**。装饰是最后才轮到考虑的事，多数时候根本轮不到。

## 三个数字

### 行长

行太长，眼睛回扫时容易串行；行太短，回扫本身变得过于频繁。经典区间是 50–75 字符：

- 少于 45 字符：回扫频率过高，阅读节奏被打断
- 66 字符左右：Bringhurst 给出的经验最优值
- 超过 80 字符：回扫开始出错，读者会不自觉地用手指或鼠标辅助

实现上，用字符单位而不是像素，让约束跟着字号一起缩放：

```css
.reading-column {
  max-width: 65ch;
  font-size: 1.125rem;
  line-height: 1.6;
}
```

### 行高

行高和行长是一对。行越长，越需要更大的行高来帮眼睛定位下一行的起点。

| 场景 | 桌面端 | 移动端 |
| --- | --- | --- |
| 正文 | 1.5–1.6 | 1.3–1.45 |
| 标题 h2–h4 | 1.1–1.2 | 1.1–1.2 |
| 展示字 | ~1.0 | — |

展示字配 `letter-spacing: -0.02em` 到 `-0.04em`，大字号下的默认字距会显得松散。

### 层级

用 Perfect Fourth（1.333）作为通用比例，只有在编辑类、标题驱动的场景才值得动黄金比例。

但真正重要的是另一条规则：**不要为了视觉尺寸而跳级**。H2 后面直接跟 H4，屏幕阅读器会读出一个断裂的大纲。

> 尺寸由 CSS 控制，语义顺序服务于屏幕阅读器。这两件事经常被混为一谈。

## 装饰的边界

配色、圆角、阴影都应该服务于已经成立的排版，而不是去弥补它。当行的度量和层级都对了，你会发现能加的东西非常少——而那正是它看起来干净的原因。

## 为什么用 ch 而不是 px

字符单位会跟着字号一起缩放。当你把正文从 18px 调到 17px，或者用户把浏览器默认字号从 16px 调到 20px，`65ch` 会自动维持大约 65 个字符的度量，而 `640px` 不会。

这一点对中文尤其重要。中文字符是全角，`1ch` 等于一个字形宽度，因此 `65ch` 在中文下实际会容纳约 65 个汉字——这比拉丁文字下同样长度的行看起来"短"，因为汉字承载的信息密度更高。中文正文的舒适区间通常在 30–45 字，所以如果站点以中文为主，建议把度量收紧到 `max-width: 38em` 附近，而不是照搬拉丁排版的经验值。

### 缩放的两条边界

- **字号下限**：移动端不要低于 16px。更低的值在暗色模式下可读性会显著下降，这是由笔画对比度而不是视觉偏好决定的。
- **行高随行长变化**：长行需要更大的行高，短行需要更小的。移动端行更短，把行高压到 1.3–1.45 反而比维持 1.6 更紧凑好读。

## 层级：比例与语义要分开

用 Perfect Fourth（1.333）作为通用模块化比例，只有在编辑类、标题驱动的场景才值得动黄金比例（1.618）。但比例管的是**尺寸**，不是**语义**：

> 尺寸由 CSS 控制，语义顺序服务于屏幕阅读器。这两件事经常被混为一谈。

实践中常见的错误是：为了让某个标题看起来小一点，把它从 `h2` 降成 `h4`。屏幕阅读器读到的是一个断裂的大纲，而"小一点"这个需求用一个 class 就能解决。

## 度量之外还剩什么

把度量、行高、层级三项确定之后，一个阅读页面大概只剩下三件事要处理：对比度、代码块的可用性、以及**克制**。

- 对比度必须实测。落在这套配色上的 `#87c5d1` 只有 1.84:1，它适合做色块，不适合承载文字。
- 代码块必须能水平滚动，也必须能键盘聚焦，否则长行代码会毁掉整页的度量。
- 剩下的加一个算一个，都是在削弱已经成立的东西。
