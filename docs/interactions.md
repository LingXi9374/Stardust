# 交互与查看器

这篇写给要改动效或查看器的人。站内有三处交互值得单独说：页面切换过渡、文章页的浮动操作、两个刻意分开实现的查看器。

## 页面切换：沉入与浮出

旧页向下沉、新页自下方浮起。样式在 `app/assets/css/main.css` 的 `.page-*` 规则里。

过渡必须走 `<NuxtPage>` 自己的 `transition` prop（`app/app.vue`）：

```vue
<NuxtPage :transition="{ name: 'page', mode: 'out-in' }" />
```

不能自己在默认插槽里包一层 `<Transition>`。Nuxt 内部只认三个来源（`node_modules/nuxt/dist/pages/runtime/page.js`）：

```js
const hasTransition = !!(props.transition ?? routeProps.route.meta.pageTransition ?? appPageTransition)
```

插槽内容会被再包进一层 `<Suspense>`，外面手写的那层 `<Transition>` 在这个结构里不会触发。写了等于没写，而且不会有任何报错。

动画作用在整个子页面上，不逐个元素错峰。一篇长文有几百个节点，错峰意味着要为几百个合成层排队，正文得等动画铺完才全部可见；单个容器的 `transform` + `opacity` 全程留在合成器上，代价固定且极低。

- `mode="out-in"` 而不是重叠。重叠需要给离场元素绝对定位，长文会瞬间脱离文档流、页面高度跳一下。
- 时长刻意短：进入 200ms、离开 140ms，位移不超过 12px。导航反馈要快到来不及注意，不是一段表演。
- `prefers-reduced-motion: reduce` 下把过渡设为 `none` 并清掉位移，不是把时长调到 0。

验证过渡真的在跑：把 `.page-leave-active` 的时长临时改成 `20000ms`，再点一个导航链接，旧页面会明明白白停在屏幕上慢慢淡出。截图往往比动画慢，用正常时长抓不到中间帧，很容易误判成没生效。

## 文章页的浮动操作

`app/components/blog/ReadingActions.vue`。向下滚过 600px 后，右下角出现「回到顶部」与「回到 Contents」两个按钮。

滚过一屏才出现，是因为刚进文章时头部那条「← Contents」已经够用，一上来就挂两个按钮属于噪音。位置选右下：左侧是固定侧栏，正文居中偏左，右下是唯一不会压住内容的角落。

实现上有两个细节：

- 滚动监听是 `passive` 的，并用 `requestAnimationFrame` 合并成每帧一次。回调里直接读 `scrollY` 会触发强制同步布局。
- 「回到顶部」的平滑滚动受 `prefers-reduced-motion` 控制，减弱动效时改成瞬间跳转。

## 照片查看器

点击文章里的任意图片（封面或正文引用）即可打开。三个文件：`app/components/blog/PhotoViewer.vue` 是界面，`app/composables/usePhotoViewer.ts` 是状态，`app/plugins/photo-viewer.client.ts` 是入口。

标记约定：给容器加 `data-photo`（`BlogImage` 的根是 `div`，属性落在那里），查看器取其中第一个 `<img>`；正文图片由 Markdown 渲染器直接把属性打在 `<img>` 上，两种都能识别。入口只接管左键且没有修饰键的点击，把「在新标签页打开图片」留给浏览器。

- `←` / `→` 或左右按钮切换，首尾循环
- 底部一排缩略图可直接跳转，当前张有强调边框
- `Esc` 关闭；关闭后焦点回到打开它的元素
- 打开时锁住背景滚动（`html[data-photo-viewer]`，样式在 `app/assets/css/content.css`）

右上角一排按钮，关闭在最右：

| 按钮 | 行为 |
| --- | --- |
| − / ＋ | 5 档缩放（1× 到 4×），到顶到底自动禁用 |
| ⟲ | 复位：回到 1× 并清掉平移量；未缩放且未平移时禁用 |
| 幻灯片 | 每 4 秒自动翻页；空格键也可切换。手动翻页会重置计时 |
| 缩略图栏 | 显示或隐藏底部整排缩略图 |
| 全屏 | 走浏览器 Fullscreen API，图标随 `fullscreenchange` 同步，按 F11 或 Esc 退出也能跟上 |

放大后图片可拖动平移，鼠标指针变抓手（拖动中变握紧的手）。平移范围限制在「图片比画布大出的那一圈」内。只有放大状态才能拖动：1× 时图片已完整可见，此时按下不抢事件。换到下一张会自动回到 1×，上一张的缩放位置对新图没有意义。

缩放与平移都用 `transform` 表达（`translate(...) scale(...)`，`transform-origin: center`），与图表查看器同一套做法。换成改 `width` / `height` 的写法会往左上角跑，原因记在下面图表查看器一节。

两个实现细节：边界按图片实际渲染尺寸算而不是容器尺寸，否则 1× 时长图被高度限制，用容器尺寸会给出过大的范围，能把图拖到一半是空白；尺寸只在换图、改缩放、改窗口、进出全屏时量一次并缓存，拖动过程中不再读布局。

性能上的取舍：图片清单在点击那一刻才扫描 DOM，不在页面加载时预建。一篇文章可能引用几十张图，事前扫描既浪费又容易和懒渲染打架。缩略图直接用大图的地址，文章里那张图已经在浏览器缓存里，再取一次不会产生新请求。打开后只预热左右相邻的两张。

## 图表查看器

逻辑在 `app/plugins/content.client.ts`。Mermaid 与 PlantUML 统一住在 4:3 的圆角画板（`.dg`）里，不这么做的话，甘特图那种狭长的输出会把版面切成一道很扁的横条，文字挤到看不清。

画板右上角在悬停或键盘进入时显形：

| 控件 | 行为 |
| --- | --- |
| − / ＋ | 5 档缩放（1× 到 4×），到顶到底自动禁用 |
| ⟲ | 复位：回到 1× 并清掉平移量；未缩放且未平移时禁用 |
| 全屏 | 把图表搬进固定舞台；再点一次或按 `Esc` 退出，全屏时右上角出现圆形关闭按钮 |

放大后画板可以拖动。1× 时图表已完整可见，此时按下留给「点空白退出全屏」和正常的页面滚动。平移范围限制在内容比画板大出的那一圈内，图表不会被拖出视野找不回来。

缩放与平移同样用 `transform` 与三个 CSS 变量（`--dg-zoom`、`--dg-x`、`--dg-y`）表达。

全屏把图表整个搬进一个挂在 `<body>` 上的固定舞台（`.dg-stage`），原位留一个同尺寸的虚线空槽（`.dg--slot`），退出时按空槽放回。不直接给 `.dg` 加 `position: fixed`：正文是 `v-html` 注入的内容，固定定位的包含块未必是视口，那样写的结果是图表从原位消失却没有铺满屏幕。留空槽而不是注释，是因为注释不占版面，那块会直接塌掉，读者看到的就是「图表没了」。

缩放这块走过三条弯路，都记在这里免得再踩：

1. `max-width: calc(100% * zoom)` 只是抬高上限，图本来就比上限小，点了没有任何反应。
2. 改成按倍数设定 `width` / `height` 虽然能放大，但长大的方向由容器排布决定；为了能滚到左上角还得把居中改成 `flex-start`，结果就是放大往左上角跑。而且居中溢出在滚动容器里是滚不到左上角的，这是个死结。
3. `.dg--plantuml` 曾经是 `display: grid`：grid 行是 `auto` 尺寸时，子项的 `height: 100%` 与行高互相依赖，属于循环百分比，按规范退化成 `auto`，于是只剩 `width: 100%` 生效，图被拉满画板宽度并裁切。flex 容器在确定高度下没有这个循环。

另外 Mermaid 会在根 `<svg>` 上内联 `style="max-width: Npx"`，内联样式优先级高于样式表，渲染后要把它摘掉。

Mermaid 的渲染时机也调整过：每个图表只渲染当前主题那一次，另一套等真的切过去再补。早先的写法是一次把亮暗两套都渲出来，一页十来个图表就是二十多次渲染、每次都重新 `initialize`，图表要等很久才出现。渲染还串行排队，因为 `mermaid.render` 内部共用一个临时容器，并发会互相踩。`securityLevel` 设为 `strict`，图表源码里的 HTML 一律不解析。

## 为什么是两个查看器

两个查看器的观感相近，都是「半透明黑底加右上角圆形关闭按钮」，但交互模型完全不同：一个是多张之间切换，一个是单张缩放平移。合并成一个会让两边都变复杂。共享的只有缩放表达方式与那套 `transform` 变量。
